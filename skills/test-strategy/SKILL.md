# 测试策略

目标不是"提高覆盖率"，而是**让真实的故障模式在合并前暴露，且代价可接受**。测不到故障的测试是负债：它会在重构时阻碍你，却不阻止你出错。

## 使用方法

**你会怎么说**
- `这块逻辑该怎么测`
- `新项目测试怎么搭`
- `我这个改动需要补哪些测试`
- `CI 太慢 / 这个测试老是偶发失败`

**我需要什么**（缺失时先问，不猜）
- 被测对象：模块/接口/命令，以及它**已知的历史故障**（线上事故、回滚过的提交）
- 约束：CI 时长上限、能否起容器/数据库、是否允许引入测试框架依赖
- 团队的验收习惯：靠 CI 门禁，还是靠人工回归

**我会先跑**
```bash
# 现状盘点：有没有测试、跑多久、多少失败
<项目测试命令> --listTests            # 或 ls 测试目录
<项目测试命令>                        # 记录 passed/failed/耗时
# 历史故障在哪：已修复 bug 的提交有没有配测试
git log --oneline --grep="fix" -20
```

**产出**：见 §7 输出格式——分层配比表 + "先写这 N 个测试"的可执行清单，而不是泛泛的"建议补充单元测试"。

**边界**：不为了覆盖率数字写测试；不替用户改生产代码（除非要求）。

## 1. 先问清三件事

1. **要防住什么故障**：列出可观测的失败模式（"并发下丢更新"、"金额四舍五入偏差"、"升级后旧配置读不出"），不是"要有测试"
2. **在哪一层测最便宜**：见 §2，能单测覆盖的逻辑不要用 E2E
3. **时间预算**：CI 目标时长（如 PR 级 ≤ 5 分钟）决定慢测试的去向

## 2. 分层与配比

| 层 | 覆盖什么 | 代价 | 不该放这里 |
|---|---|---|---|
| 单元测试 | 纯逻辑、边界、状态机、解析/格式化 | 毫秒 | 需要真实 IO 才能验证的事 |
| 集成测试 | 模块间契约、DB/队列/HTTP 边界、事务 | 秒 | 纯计算逻辑 |
| 契约测试 | 对外 API/序列化格式的兼容性 | 秒 | 内部实现细节 |
| 端到端 | 用户关键路径（登录、下单、发版） | 分钟、易 flaky | 分支细节（应有无数组合，E2E 只留主干） |
| 快照/黄金文件 | 输出格式稳定（编译器、模板、报告） | 快 | 会自然频繁变动的内容 |
| 性能基准 | 热路径回归（见 `perf-investigate`） | 分钟 | 功能正确性 |

判断口径：**能在更快的一层测出同样故障，就不要放慢层**。E2E 只留"主干路径 + 跨系统集成"，每个用例都要能说出"它挡住了哪个单测挡不住的事故"。

## 3. 该测什么（按优先级）

1. **边界与异常**：0 / 空集合 / 单元素 / 超长 / null / 类型不符 / 超时 / 部分失败
2. **状态迁移**：合法与非法迁移、重复提交、幂等重放
3. **并发与顺序**：并行写、锁内 await、事件乱序、重试
4. **契约与兼容**：序列化字段新增/删除、旧客户端读新数据、配置缺省
5. **权限与越权**：谁能调用、跨租户/跨用户访问
6. **每个已修 bug 一条回归测试**（修复前失败、修复后通过）

**不该写**：getter/setter、纯转发、一行业务逻辑的包装层、实现细节（私有方法调用次数）——这类测试只在重构时碍事。

## 4. 什么才算一个合格的测试

- **能失败**：写完故意破坏被测代码一次，确认测试变红；不变红的测试没有价值
- **断言具体值**：`assert x == 3`，不用 `assertNotNull(x)` / `assertTrue(result)`
- **一个测试一个原因**：失败信息能直接指向原因，不需要再读代码
- **不依赖环境**：固定时钟、固定随机种子、临时目录、本地端口 0、不访问真实网络
- **不依赖顺序**：单独跑和全量跑结果一致
- **命名描述场景**：`并发写入时不丢更新`，不用 `test2` / `testFix`

## 5. 覆盖率怎么用

- 行覆盖是**"哪些代码从没被执行"的清单**，不是质量分数
- 分支覆盖优先于行覆盖；错误分支和边界分支优先于 happy path
- 设阈值只做**下限门禁**（如不低于当前值），禁止为了达标写无断言测试
- 报告里明确指出：哪些关键路径是**故意不测**（如依赖外部硬件的分支），以及理由

## 6. 落地结构

- 目录与命名跟随仓库既有约定；没有约定时按被测单元就近放置
- CI 分两档：`fast`（单测 + 契约，PR 必跑）、`slow`（集成 + E2E，合并后或定时跑）
- 失败输出必须包含**本地可复现的命令**
- flaky 处理三步：先隔离（标记并单列），再修根因（等待、时序、共享状态），**不许用自动重试掩盖**
- 老项目没测试时：不追覆盖率，只给"最危险 3 条路径"补特征测试（固定当前行为），再逐步加新

## 7. 输出格式

```
## 结论
<一句话：现有测试够不够 / 需要补哪几类>

## 分层配比建议
| 层 | 数量级 | 放什么 | 时长预算 |

## 先写这 N 个测试（按性价比排序）
1. `<名称>` — 覆盖的故障：<具体失败模式>
   放哪层：<单测/集成/…>  为什么在这里：<昂贵层挡不住的差异>
   关键断言：<写清期望值>

## 现在不写 / 故意不测
- <项> — 理由

## 工程化
- 命令：<本地怎么跑>
- CI 分档与门禁：<...>
- flaky 处理：<...>
```

## 8. 边界

- 不把"补测试"当成重构的前置借口拖慢交付：只补即将改动路径的特征测试
- 不为覆盖率写无断言的测试；不为通过门禁删除有意义的用例
- 用户只要策略时，只给策略与清单，不批量生成测试代码（除非明确要求）
